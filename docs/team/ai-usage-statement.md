## 1. 声明目的

本声明用于明确团队在课程项目中使用生成式 AI 工具的边界、披露方式与责任归属，确保：

1. AI 只作为辅助工具，不替代团队成员的理解、判断与验收责任。
2. 不违反课程学术诚信要求，不将 AI 生成内容冒充为个人独立完成。
3. 不因使用 AI 引入安全、隐私或知识产权风险。

## 2. 允许的使用场景

- **学习与理解**：解释框架机制、算法思路、错误信息含义。
- **编码辅助**：生成样板代码、补全重复性代码、给出重构建议；最终代码必须由成员逐行审查。
- **测试辅助**：生成测试用例草稿、边界条件清单；由成员核对预期结果并运行验证。
- **文档辅助**：润色语句、生成目录与表格草稿；事实、数据与结论必须由成员确认。
- **调试辅助**：根据日志/堆栈给出排查方向；不得直接粘贴含密钥或他人隐私的内容。

## 3. 禁止的使用场景

1. 直接提交未经审查的 AI 生成代码，尤其是认证、权限、判题沙箱、数据库删除等高风险逻辑。
2. 将课程提供的他人代码、未公开测试数据、教师材料输入外部模型。
3. 在提问或代码中粘贴真实 API Key、密码、数据库连接串、学生个人信息。
4. 用 AI 代替本人完成答辩讲解或伪造实验数据、测试结果、运行截图。
5. 生成或引入来源不明、许可不清的代码/素材。
6. 绕过课程规定的独立完成要求（如闭卷测验、个人作业）。

## 4. 披露要求

### 4.1 代码与提交

- 当某次提交的代码有实质性部分由 AI 生成或改写时，在 commit message 末尾添加：

```
AI-Used: <工具名称> (<用途>)
Reviewed-By: <成员姓名>
```

示例：

```
feat: 增加自定义输入运行接口

AI-Used: CodeArts Agent (生成 DTO 与单元测试草稿)
Reviewed-By: 张三
```

- PR 描述中说明 AI 参与范围（需求分析 / 代码草稿 / 测试 / 文档），以及人工修改与验证方式。

### 4.2 文档

- 在文档修订记录或附录中注明 AI 辅助的章节（如“第 6 节优先级表由 AI 生成草稿，涂春晖复核”）。
- 引用的外部资料需给出处，不得把 AI 输出当作权威来源。

## 5. 责任与审查

1. **审查责任**：AI 生成内容的第一责任人是对应模块负责人；合并前必须理解代码逻辑并能解释实现原理。
2. **验证责任**：涉及业务规则的代码必须有可执行验证（接口测试、页面操作、边界用例），不能仅凭“看起来正确”。
3. **安全责任**：合并前检查是否泄露密钥、是否放宽权限、是否引入危险命令或未过滤输入。
4. **可追溯**：保留关键 prompt/对话摘要（不含敏感信息）与修改记录，便于课程检查。

## 6. 数据与隐私

- 不在外部模型中输入：真实用户密码、JWT、API Key、数据库凭据、学生姓名/学号等个人信息。
- 需要提供上下文时，使用脱敏数据或最小必要片段。
- AI 助教功能中的用户 API Key 由用户自行配置，前端不回显明文，日志不记录密钥。
- 发现密钥泄露时立即轮换并在团队内通报。

## 7. 违规处理

1. 发现未披露的 AI 生成内容：要求补充披露并重新审查。
2. 发现直接提交未审查代码导致缺陷：由提交人修复，并在周会记录。
3. 发现泄露密钥或隐私：立即停止使用相关配置、轮换凭据、评估影响。
4. 严重违反学术诚信的，按课程与学校规定处理，团队不承担代为隐瞒责任。
