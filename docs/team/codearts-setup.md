# CodeArts 项目成员与需求规划配置指引

> 本指引对应本周任务第（3）项：在 CodeArts 上完成项目成员添加和需求规划管理。
> CodeArts 不同版本/套餐的菜单名称可能略有差异，以下步骤以通用项目管理界面为准；如界面不一致，以实际入口为准。

## 1. 配置前准备

1. 确认 6 名成员均已注册 CodeArts 账号（华为云账号）。
2. 准备成员信息表：姓名、账号、角色、主备职责（见 `docs/team/team-charter.md` 第 2、9 节）。
3. 确认项目仓库已创建，且项目经理拥有项目管理员权限。
4. 准备需求清单：`docs/requirements/backlog.csv`（Epic / Feature / Story / Task、优先级、故事点、迭代、验收标准）。

## 2. 添加项目成员

### 2.1 进入成员管理

1. 打开 CodeArts 项目首页。
2. 进入「设置」→「成员管理」（或「项目设置」→「成员与权限」）。
3. 点击「添加成员」。

### 2.2 邀请成员

1. 输入成员账号（邮箱/手机号/华为云账号），或复制邀请链接发送给成员。
2. 为每位成员选择角色：
   - 项目经理（成员 A）：项目管理员 / 需求管理。
   - 后端成员（B/C/D）：开发者（代码、工作项、流水线）。
   - 前端成员（E/F）：开发者（代码、工作项）。
   - 需要跨模块评审的成员：开发者 + 代码评审权限。
3. 确认后成员会收到邀请，成员接受后即可访问项目与仓库。

### 2.3 权限检查

- 每位成员能打开项目首页、代码仓库、工作项列表。
- 至少 2 人拥有成员管理/工作项配置权限，避免单点。
- 学生账号不应拥有删除仓库等高风险权限。

## 3. 需求规划管理

### 3.1 工作项层级

采用四级结构，与 `backlog.csv` 对应：

| 层级 | 说明 | 示例 |
| --- | --- | --- |
| Epic | 大的业务目标，跨迭代 | E-01 用户与权限 |
| Feature | 可交付的功能块 | F-03 代码编辑与提交 |
| Story | 用户价值单元，必须带验收标准 | US-05 作为学生，我想提交代码获得评测 |
| Task | 1 人天以内的执行任务 | T-01 完成用例建模前 6 步 |

### 3.2 创建迭代

1. 进入「需求管理」→「迭代/计划」。
2. 创建 4 个迭代（与用例分析文档一致）：
   - Sprint 1：需求与原型（第 1–2 周）
   - Sprint 2：账号、题库、提交（第 3–4 周）
   - Sprint 3：评测结果、题目管理（第 5–6 周）
   - Sprint 4：体验与扩展、测试与验收预演（第 7–8 周）
   - 如课程要求 10 周，可增加 Sprint 5（第 9–10 周）用于测试、文档、验收。
3. 为每个迭代设置起止日期与目标。

### 3.3 录入工作项

**方式 A：手工录入（推荐首次使用）**

1. 新建 Epic，填入编号（E-01 等）、标题、描述、负责人。
2. 在 Epic 下新建 Feature，选择父项。
3. 在 Feature 下新建 Story，填写：
   - 标题：用户故事句式；
   - 描述：背景 + 价值；
   - 验收标准：对应 `use-case-specs.md` 的 AC 编号与 Given–When–Then；
   - 优先级：P0/P1/P2；
   - 故事点：1/2/3/5/8；
   - 迭代：Sprint N；
   - 负责人：成员姓名。
4. 在 Story 下拆 Task（≤1 人天），指派负责人与截止日期。
5. 关联用例编号（UC-xx）到工作项描述中，便于追踪。

**方式 B：导入**

1. 查看 CodeArts 是否提供工作项导入模板（通常支持 Excel/CSV）。
2. 将 `backlog.csv` 的列映射到模板字段：工作项类型、标题、父项、优先级、故事点、迭代、负责人、状态、验收标准。
3. 先导入 2–3 条试运行，确认层级与字段正确后再全量导入。
4. 导入后逐条检查父子关系与迭代归属，避免全部落在默认迭代。

### 3.4 看板与状态流

- 状态：待办 → 进行中 → 待评审 → 已完成。
- 每列设置 WIP 限制（进行中 ≤ 2/人），避免并行过多。
- 每日站会前更新工作项状态与剩余工时。
- 验收前 1 周冻结新 Story，只保留缺陷与文档任务。

### 3.5 关联代码与评审

- 在 Story/Task 中关联分支、提交、合并请求。
- 合并请求描述填写关联工作项编号（如 `US-05`）与验证结果。
- 高风险改动（认证、权限、判题、删除）至少 2 人评审。

## 4. 本周完成检查清单

- [ ] 6 名成员均已加入项目，角色正确。
- [ ] 每人都能访问代码仓库与工作项列表。
- [ ] 已创建 Epic/Feature/Story/Task 四级工作项。
- [ ] 已创建 4–5 个迭代并设置起止日期。
- [ ] 所有 Must 用例对应的 Story 已录入并指派负责人。
- [ ] 每个 Story 都有验收标准（引用 AC 编号）。
- [ ] 看板状态流已配置，WIP 限制已设置。
- [ ] 工作项与用例分析、规格文档中的编号一致。
- [ ] 团队章程中的成员姓名与 CodeArts 成员列表一致。
