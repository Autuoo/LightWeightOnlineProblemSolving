## 03 需求构思（约 300 字，400 字以内）

```
项目背景：软件工程课程需要可演示、可分工、可度量的完整工程实践。现有在线判题平台多为重型系统，部署与维护成本高，不适合课程规模；而学生日常练习又普遍缺少即时反馈。

核心业务：建设轻量在线判题系统，支持 Python、C++、Java 提交，采用异步评测链路（提交—编译—逐点运行—结论），通过 WebSocket 实时推送判题状态，提供逐点结果、幂等提交与队列背压；另设 AI 助教模块，只读取脱敏后的失败摘要，给出启发式提示。

边界声明：不做竞赛排名、组队与抄袭检测；仅支持上述三门语言；不部署分布式多节点；AI 助教不返回测试点数据，不给出正确答案或可提交代码。
```

## 附：需求构思的三段拆解（组会讲解用）

### 项目背景

课程项目需要在一学期内完成需求、设计、实现、测试、部署的完整闭环，并且要能公平地切成 6 份工作量。重型 OJ 平台（分布式调度、多语言沙箱集群、竞赛体系）远超课程规模；而学生做题的真实痛点是"提交后不知道错在哪"，反馈链条断裂。

### 核心业务

- **提交受理**：参数校验、幂等判定（10 分钟窗口内相同代码复用结果）、队列满时背压拒绝
- **异步评测**：`PENDING → COMPILING → RUNNING → AC/WA/TLE/MLE/RE/CE` 状态机，逐测试点执行，首个失败点终止
- **实时反馈**：WebSocket 推送终态，前端断线自动降级为轮询
- **AI 助教**：只读取脱敏失败摘要（失败点序号、类型、输出行数与字符长度），给出方向性提示

### 边界声明

| 明确要做 | 明确不做 |
|---|---|
| 单机部署、课程规模 | 竞赛排名、组队、抄袭检测 |
| 三种语言 | 多语言全支持 |
| 逐点判定 | 浮点误差比对、Special Judge |
| 启发式提示 | 直接给答案或可提交代码 |
| 单机异步队列 | 分布式多节点调度 |
