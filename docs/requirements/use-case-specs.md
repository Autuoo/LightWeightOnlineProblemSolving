## 0. 用例规格模板

每个核心用例按以下字段填写，保证可直接用于设计、测试与验收：

| 字段 | 说明 |
| --- | --- |
| 用例编号 / 名称 | 唯一编号与动宾结构名称 |
| 范围 / 层级 | 所属子系统；用户目标级或子功能级 |
| 主要 / 次要参与者 | 触发用例的行为者；外部系统 |
| 利益相关者与利益 | 谁关心、关心什么 |
| 前置条件 | 用例开始前必须为真 |
| 后置条件 | 成功/失败后的系统状态 |
| 触发事件 | 参与者发起用例的动作 |
| 主成功场景 | 编号步骤，覆盖正常路径 |
| 扩展场景 | 以主场景步骤号 + 字母标注异常/分支 |
| 业务规则 | 必须遵守的约束（BR-xx） |
| 非功能需求 | 性能、安全、可用性等 |
| 数据与接口约束 | 关键字段、接口、存储限制 |
| 优先级 | MoSCoW + RICE（可选） |
| 迭代 / 负责人 | 计划完成的迭代与负责人 |
| 验收标准 | Given–When–Then，编号 AC-xx-n |

## UC-01 注册账号

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-01 / 注册账号 |
| 范围 / 层级 | OJ 学生端 / 用户目标级 |
| 主要参与者 | 学生（未登录用户） |
| 次要参与者 | 无 |
| 利益相关者与利益 | 学生：快速开始使用；教师：账号来源可控 |
| 前置条件 | 用户未登录；系统可访问注册接口 |
| 后置条件（成功） | 创建角色为 STUDENT 的账号并写入登录态，进入题库 |
| 后置条件（失败） | 不创建账号，保留表单并提示原因 |
| 触发事件 | 在登录页点击「立即注册」并提交注册表单 |
| 主成功场景 | 1. 用户从登录页切换到注册表单。<br>2. 用户输入用户名、可选昵称、密码、确认密码。<br>3. 前端校验用户名格式、密码长度、两次密码一致。<br>4. 前端调用 `POST /api/auth/register`。<br>5. 后端校验用户名唯一，使用 BCrypt 加密密码，创建 STUDENT 账号。<br>6. 后端签发 JWT，返回 token 与用户信息。<br>7. 前端保存登录态并跳转题库。 |
| 扩展场景 | 3a. 用户名不符合 3–32 位字母/数字/下划线：提示格式错误，不提交。<br>3b. 密码长度不在 6–64：提示长度要求。<br>3c. 两次密码不一致：提示重新输入。<br>5a. 用户名已存在：返回「用户名已被注册」，保留表单。<br>5b. 并发注册撞唯一键：同样提示用户名已存在。<br>4a. 网络或服务异常：提示无法连接后端，可重试。 |
| 业务规则 | BR-01 用户名仅允许字母、数字、下划线，长度 3–32，全局唯一。<br>BR-02 密码长度 6–64，仅存 BCrypt 哈希。<br>BR-03 昵称可选，最长 32 字符，默认为用户名。<br>BR-04 自助注册只能创建 STUDENT，不允许指定管理员角色。 |
| 非功能需求 | 注册接口 1 秒内返回；密码与 token 不写入日志；表单错误提示需可见。 |
| 数据与接口约束 | `POST /api/auth/register`，请求含 username、nickname、password；成功返回 token、expiresIn、user。 |
| 优先级 | Must；RICE 估算见分析文档 6.2 |
| 迭代 / 负责人 | Sprint 2 / 涂春晖 |
| 验收标准 | AC-01-1 Given 合法用户名与密码，When 提交注册，Then 账号创建成功并自动登录进入题库。<br>AC-01-2 Given 已存在的用户名，When 提交注册，Then 返回 400 且提示「用户名已被注册」。<br>AC-01-3 Given 两次密码不一致，When 提交，Then 前端拦截并提示，不发送请求。 |

## UC-02 登录与退出

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-02 / 登录与退出 |
| 范围 / 层级 | OJ 全端 / 用户目标级 |
| 主要参与者 | 学生、管理员/教师 |
| 次要参与者 | 无 |
| 利益相关者与利益 | 用户：安全进入系统；教师：管理功能仅管理员可用 |
| 前置条件 | 已注册且账号状态为启用 |
| 后置条件（成功） | 建立 JWT 会话，按角色进入对应界面 |
| 后置条件（失败） | 不建立会话，停留在登录页并提示 |
| 触发事件 | 提交登录表单，或点击「退出登录」 |
| 主成功场景 | 1. 用户输入用户名与密码。<br>2. 前端调用 `POST /api/auth/login`。<br>3. 后端校验密码哈希与账号状态，签发 JWT（有效期 2 小时）。<br>4. 前端保存 token 与用户信息，跳转题库或管理页。<br>5. 用户点击退出，前端清除本地 token 与用户信息并回到登录页。 |
| 扩展场景 | 2a. 用户名或密码错误：提示「用户名或密码错误」，不区分具体原因。<br>2b. 账号被禁用：提示账号不可用。<br>3a. token 过期或非法：后续请求返回 401，前端清除登录态并跳转登录页。<br>1a. 表单为空：前端提示请输入用户名和密码。 |
| 业务规则 | BR-05 密码校验使用 BCrypt，禁止明文比较与存储。<br>BR-06 管理员与学生在同一登录入口，按 role 控制菜单与接口权限。<br>BR-07 JWT 失效后必须重新登录，不允许前端伪造角色。 |
| 非功能需求 | 登录接口 1 秒内返回；连续失败不泄露账号是否存在；退出后浏览器返回不能恢复受限页面。 |
| 数据与接口约束 | `POST /api/auth/login`；`GET /api/auth/me` 用于恢复会话；Authorization: Bearer。 |
| 优先级 | Must |
| 迭代 / 负责人 | Sprint 2 / 涂春晖 |
| 验收标准 | AC-02-1 Given 正确账号密码，When 登录，Then 进入系统且菜单按角色显示。<br>AC-02-2 Given 错误密码，When 登录，Then 返回统一错误提示且不泄露账号是否存在。<br>AC-02-3 Given 学生已登录，When 直接访问 `/api/admin/**`，Then 返回 403。<br>AC-02-4 Given 已登录，When 点击退出，Then 本地登录态清空并回到登录页。 |

## UC-05 编写并提交代码

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-05 / 编写并提交代码 |
| 范围 / 层级 | OJ 学生端 / 用户目标级 |
| 主要参与者 | 学生 |
| 次要参与者 | 判题沙箱（系统内部） |
| 利益相关者与利益 | 学生：获得自动评测；教师：统一评测标准 |
| 前置条件 | 已登录；目标题目存在且 `visible=1`；题目已配置测试点 |
| 后置条件（成功） | 生成提交记录（PENDING），异步进入评测，最终进入终态 |
| 后置条件（失败） | 不生成提交记录，或记录为 REJECTED 并提示原因 |
| 触发事件 | 点击「提交评测」或按 `Ctrl/⌘ + Enter` |
| 主成功场景 | 1. 学生选择题目的可用语言（Python 3 / C++17 / Java 17）。<br>2. 学生在编辑器中编写代码。<br>3. 学生点击提交，前端调用 `POST /api/submissions`。<br>4. 后端校验语言、题目可见性、代码长度，计算代码哈希。<br>5. 若存在相同用户+题目+语言+代码的最近提交，直接复用其结果。<br>6. 否则创建 PENDING 提交，进行可疑代码标记，投递判题任务。<br>7. 返回提交 ID，前端进入结果面板并订阅/轮询状态。 |
| 扩展场景 | 3a. 代码为空：前端提示，不提交。<br>4a. 语言不支持：返回 40002 不支持的语言。<br>4b. 题目不可见：返回「题目不存在或不可见」。<br>4c. 未配置测试点：评测返回 RE 并写明「题目未配置测试点」，需管理员补数据。<br>6a. 判题队列已满：提交标记 REJECTED，提示稍后重试。<br>7a. WebSocket 不可用：降级为轮询，仍能获取终态。 |
| 业务规则 | BR-08 代码长度 ≤ 65536 字符；语言必须在支持列表内。<br>BR-09 相同代码重复提交复用最近结果，避免重复占用评测资源。<br>BR-10 隐藏测试点内容不得返回学生端。<br>BR-11 命中打表/固定输出特征时仅标记 suspicious，不直接扣分。 |
| 非功能需求 | 提交接口 1 秒内返回 submissionId；单测试点执行不超过题目时限；评测异步执行不阻塞请求线程。 |
| 数据与接口约束 | `POST /api/submissions`，请求含 problemId、language、code；响应含 submissionId、status、reused。 |
| 优先级 | Must |
| 迭代 / 负责人 | Sprint 2–3 / 钱嘉鑫、涂春晖 |
| 验收标准 | AC-05-1 Given 合法代码与可见题目，When 提交，Then 返回 submissionId 且状态为 PENDING。<br>AC-05-2 Given 不支持的编程语言，When 提交，Then 返回 40002 且不创建记录。<br>AC-05-3 Given 相同代码连续提交两次，When 第二次提交，Then 复用最近结果（reused=true）。<br>AC-05-4 Given 题目无测试点，When 提交，Then 结果为 RE 且错误信息明确提示未配置测试点。<br>AC-05-5 Given 评测完成，When 查询提交详情，Then 状态为 AC/WA/TLE/RE/CE 之一并带逐点结果。 |

## UC-06 查看评测结果与提交详情

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-06 / 查看评测结果与提交详情 |
| 范围 / 层级 | OJ 学生端、管理端 / 用户目标级 |
| 主要参与者 | 学生、管理员 |
| 次要参与者 | 无 |
| 利益相关者与利益 | 学生：定位错误；教师：检查班级提交情况 |
| 前置条件 | 提交记录存在；学生只能查看本人提交 |
| 后置条件（成功） | 展示状态、分数、逐点结果、编译输出与代码 |
| 后置条件（失败） | 提示不存在或无权限，不展示他人代码 |
| 触发事件 | 从结果面板点击「详情」，或从提交记录进入 |
| 主成功场景 | 1. 学生打开某个提交详情。<br>2. 后端校验归属（管理员可查看全部）。<br>3. 返回状态、得分、耗时、内存、代码、编译输出、逐点结果。<br>4. 前端展示状态徽标、分数、测试点表格与代码块。<br>5. 若提交仍在评测中，前端继续轮询/订阅直到终态。 |
| 扩展场景 | 2a. 非本人且非管理员：返回 403，不泄露代码。<br>2b. 提交不存在：返回 404 并显示空状态。<br>5a. 实时连接失败：降级轮询，不出现整页卡死。 |
| 业务规则 | BR-12 逐点结果只展示序号、状态、耗时、内存，不展示测试输入/期望输出。<br>BR-13 编译失败时展示编译输出（截断），不展示运行输出。 |
| 非功能需求 | 详情接口 1 秒内返回；页面在 1440×900 下结果表完整可见；实时更新失败不影响基本信息展示。 |
| 数据与接口约束 | `GET /api/submissions/{id}`；逐点结果来自 `submission_case_result`，序号由测试点映射。 |
| 优先级 | Must |
| 迭代 / 负责人 | Sprint 3 / 钱嘉鑫、陈益诚 |
| 验收标准 | AC-06-1 Given 本人提交，When 打开详情，Then 展示状态、分数、逐点结果且无测试点内容。<br>AC-06-2 Given 查看他人提交且非管理员，When 请求详情，Then 返回 403。<br>AC-06-3 Given 提交从 PENDING 变为终态，When 页面保持打开，Then 自动刷新为终态结果。 |

## UC-07 自定义输入运行

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-07 / 自定义输入运行 |
| 范围 / 层级 | OJ 学生端 / 子功能级（扩展 UC-05） |
| 主要参与者 | 学生 |
| 次要参与者 | 判题沙箱（系统内部） |
| 利益相关者与利益 | 学生：用自己的数据调试；教师：隐藏测试点不泄露 |
| 前置条件 | 已登录；题目可见；编辑器中有代码 |
| 后置条件（成功） | 返回运行状态与 stdout/stderr，不产生提交记录 |
| 后置条件（失败） | 返回编译错误/超时/异常信息，不产生提交记录 |
| 触发事件 | 点击工具栏「运行自测」并提交自定义输入 |
| 主成功场景 | 1. 学生点击「运行自测」，弹出自定义运行对话框。<br>2. 学生填写标准输入。<br>3. 学生点击「运行」，前端调用 `POST /api/submissions/custom-run`。<br>4. 后端校验题目可见性与语言，调用沙箱运行当前代码。<br>5. 后端返回状态（OK/CE/TLE/RE）、stdout、stderr、编译输出、耗时。<br>6. 前端在结果区展示输出与状态，不写入提交记录。 |
| 扩展场景 | 3a. 输入超过 64 KB：返回校验错误。<br>4a. 语言不支持：返回 40002。<br>4b. 编译失败：状态 CE，展示编译输出。<br>4c. 超时：状态 TLE，展示题目时限。<br>4d. 非零退出：状态 RE，展示 stderr 或退出码。 |
| 业务规则 | BR-14 自定义运行只使用学生输入的 stdin，不读取任何隐藏测试点。<br>BR-15 不创建 submission、不写逐点结果、不影响统计。<br>BR-16 时间限制与题目一致；输出超长截断展示。 |
| 非功能需求 | 同步运行请求超时上限 40 秒；界面明确提示「不产生提交记录」；结果区可滚动、等宽字体。 |
| 数据与接口约束 | `POST /api/submissions/custom-run`，请求含 problemId、language、code、input；响应含 status、exitCode、timeMs、stdout、stderr、compileOutput。 |
| 优先级 | Should |
| 迭代 / 负责人 | Sprint 4 / 钱嘉鑫、陈益诚 |
| 验收标准 | AC-07-1 Given 代码 `print(int(input())*2)` 和输入 `21`，When 运行，Then 展示 `42` 且状态为 OK。<br>AC-07-2 Given 语法错误代码，When 运行，Then 状态为 CE 并展示编译输出。<br>AC-07-3 Given 死循环代码，When 运行，Then 状态为 TLE 且耗时接近题目时限。<br>AC-07-4 Given 任意自定义运行，When 运行前后查看提交记录，Then 提交总数不变。 |

## UC-11 配置 AI 助教并提问

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-11 / 配置 AI 助教并提问 |
| 范围 / 层级 | OJ 学生端 / 用户目标级 |
| 主要参与者 | 学生 |
| 次要参与者 | 阿里云百炼（外部 AI 服务） |
| 利益相关者与利益 | 学生：获得针对当前代码的提示；教师：不代替学生完成作业 |
| 前置条件 | 已登录；学生已配置模型端点与 API Key（否则禁用入口） |
| 后置条件（成功） | 返回针对当前题目/提交的提示，记录调用轨迹 |
| 后置条件（失败） | 明确提示未配置、额度不足、超时或服务不可用 |
| 触发事件 | 学生在 AI 面板输入问题并提交，或点击预设的「思路/定位/检查点」 |
| 主成功场景 | 1. 学生打开题目/提交详情中的 AI 助教面板。<br>2. 若未配置，面板展示配置引导并禁用提问。<br>3. 学生完成配置后，输入与当前题目相关的问题。<br>4. 后端组装题目上下文与问题，调用阿里云百炼。<br>5. 返回提示文本并展示在面板中。 |
| 扩展场景 | 2a. 未配置 API Key：显示「AI 助教尚未启用」并提供「去配置」。<br>4a. 密钥无效或额度不足：提示检查配置/额度。<br>4b. 调用超时：提示稍后重试。<br>4c. 问题与题目无关：提示聚焦当前题目。<br>5a. 回答命中直接给答案的边界：提示只给思路，不提供完整答案。 |
| 业务规则 | BR-17 AI 功能按用户自配 API 启用，未配置即禁用。<br>BR-18 提示不得直接给出完整可提交答案，以思路、定位、检查点为主。<br>BR-19 API Key 不返回前端明文、不写入日志。<br>BR-20 调用记录只保留元信息，不存储完整 prompt 与用户代码全文。 |
| 非功能需求 | 调用超时 30 秒内返回或明确超时；外部服务不可用时不影响刷题主链路；密钥安全存储。 |
| 数据与接口约束 | 用户级配置表 `user_ai_config`；AI 调用记录表 `ai_hint`；提示接口按提交/题目维度调用。 |
| 优先级 | Should（依赖外部服务，不作为验收必过项） |
| 迭代 / 负责人 | Sprint 4 / 万天行、陈益诚 |
| 验收标准 | AC-11-1 Given 未配置 API Key，When 打开 AI 面板，Then 展示禁用原因与配置入口。<br>AC-11-2 Given 已配置有效 Key，When 针对当前题目提问，Then 返回与分析相关的提示。<br>AC-11-3 Given Key 无效，When 提问，Then 提示配置错误且不影响提交与自测。<br>AC-11-4 Given 任意提问，When 查看页面源码/日志，Then 不出现明文 API Key。 |

## UC-12 题目管理

| 字段 | 内容 |
| --- | --- |
| 用例编号 / 名称 | UC-12 / 题目管理 |
| 范围 / 层级 | OJ 管理端 / 用户目标级 |
| 主要参与者 | 管理员/教师 |
| 次要参与者 | 无 |
| 利益相关者与利益 | 教师：维护题库与测试点；学生：题目数据准确 |
| 前置条件 | 已登录且角色为 ADMIN |
| 后置条件（成功） | 题目与测试点按管理操作新增/更新/删除 |
| 后置条件（失败） | 数据不变，展示校验或权限错误 |
| 触发事件 | 管理员在题目管理页新建、编辑、删除题目或导入测试点 |
| 主成功场景 | 1. 管理员打开题目管理页，查看题目列表与测试点数量。<br>2. 新建或编辑题目，填写标题、题面 Markdown、难度、时限、内存、标签、样例、可见性。<br>3. 保存后系统返回题目 ID。<br>4. 管理员在测试点导入区填写题目 ID，粘贴 JSON 数组（orderNo、input、expectedOutput、score）。<br>5. 系统整体替换该题测试点并刷新数量。<br>6. 管理员可将题目设为可见，学生在题库中看到。 |
| 扩展场景 | 2a. 必填项缺失或样例格式错误：提示具体字段。<br>4a. JSON 格式错误或数组为空：提示格式问题，不导入。<br>4b. 题目 ID 填错：测试点会替换到其他题目，界面需二次确认目标题目（改进项）。<br>5a. 删除题目：确认后级联删除该题测试点、逐点结果、AI 记录与提交记录。<br>1a. 非管理员访问：返回 403。 |
| 业务规则 | BR-21 题目标题、题面、难度必填；可见性控制学生端展示。<br>BR-22 测试点导入为整体替换；建议分值合计 100。<br>BR-23 删除题目不可恢复，必须二次确认并说明影响范围。<br>BR-24 学生端不得获取测试点内容。 |
| 非功能需求 | 列表分页加载；导入 100 条以内测试点在 2 秒内完成；删除操作在事务中完成，失败回滚。 |
| 数据与接口约束 | `GET/POST/PUT/DELETE /api/admin/problems`；`POST /api/admin/problems/{id}/test-cases`；表 `problem`、`test_case`。 |
| 优先级 | Must |
| 迭代 / 负责人 | Sprint 3 / 涂春晖、余佩奇 |
| 验收标准 | AC-12-1 Given 管理员填写完整题目信息，When 保存，Then 题目创建成功并出现在列表。<br>AC-12-2 Given 合法测试点 JSON，When 导入，Then 测试点数量更新且可被评测使用。<br>AC-12-3 Given 已有提交的题目，When 确认删除，Then 题目、测试点与关联提交一并删除。<br>AC-12-4 Given 学生访问管理接口，When 请求题目管理，Then 返回 403。 |
